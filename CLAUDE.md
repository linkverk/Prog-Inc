# CLAUDE.md — инструкции по работе с Zero to Ten-X

Проект: инкрементальная игра про карьеру программиста (300 навыков в 8 ветках, 8 веточных
валют + 4 глобальных, 36 одноразовых gateway-навыков, 450 магазинных апгрейдов,
7 специализаций, prestige через смену работы).
Стек: TypeScript 5.6 + Vite 5, ESM, **без runtime-зависимостей**. Сборка — `npm run build`.

Язык кода, комментариев, UI и документации — английский (британский: «specialisation»,
как в PLAN.md). Общение с пользователем — русский.

## Правила кода

- Строгий TypeScript: `strict`, `noUnusedLocals`, `noUnusedParameters`,
  `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`, `isolatedModules` (см. `tsconfig.json`)
- Типы импортируются как `import type { ... }` — иначе `verbatimModuleSyntax` даст ошибку
- Runtime-зависимости не добавляются. Нужна библиотека — сначала обоснование, потом обсуждение
- Слои односторонние, нарушать нельзя:
  - `src/core/` — правила игры. **DOM здесь запрещён**
  - `src/data/` — контент, почти без логики
  - `src/ui/` — рендер. Читает `core`, но никогда не мутирует его состояние напрямую
- Файлы `src/data/*.generated.ts` руками не правятся. Контент меняется в
  `scripts/gen-content.mjs`, затем `npm run gen`. Сгенерированное коммитится намеренно —
  чистый checkout должен запускаться без предварительной сборки
- Без emoji в коде. Игровые символы валют (`◇ ∞ ✓ ¤ ∿ ⌖ ♥ ∴ ★`) — не emoji, они часть контента
- Комментарии — только когда добавляют смысл. Пересказ кода не нужен
- Формат save в `localStorage` — `zero10x.save.v3`. Смена формы состояния требует бампа
  версии и миграции в `src/core/state.ts`

## Организация md-файлов

Списки задач в этом файле НЕ ведутся. Роли файлов:

- **[PLAN.md](PLAN.md)** — спецификация v2, которую реализует код. Источник намерения:
  «if code and this file disagree, this file is the intent and the code is the bug».
  Это НЕ список задач и не чеклист
- **[TASKS.md](TASKS.md)** — append-only журнал выполненного.
  Формат записи: `- дата — задача — коммит`. Записи не редактируются и не удаляются
- **[README.md](README.md)** — пользовательская документация. При изменении скриптов,
  раскладки `src/` или чисел из `npm run stats` — синхронизировать
- **[wiki/](wiki/)** — база знаний по дизайну игры, отдельный Obsidian-vault со своей
  схемой в [wiki/CLAUDE.md](wiki/CLAUDE.md). Правила ведения wiki описаны там, здесь
  не дублируются. `wiki/raw/` — слой человека, неизменяемый; агент туда не пишет

### Workflow задачи

1. Понять, что задача меняет: правила (`src/core/`), контент (`scripts/gen-content.mjs`),
   рендер (`src/ui/`) или спеку (`PLAN.md`). Если меняется поведение — сначала PLAN.md
2. Реализовать. Контент — только через генератор, затем `npm run gen`
3. Прогнать проверки: `npm run typecheck`, при изменении контента ещё `npm run stats`
   и сверить числа с README.md и wiki
4. Обновить затронутые wiki-страницы, если изменились числа или механики
5. Добавить запись в TASKS.md с датой и хешем коммита
6. Этот файл обновляется только когда меняются конвенции, а не по каждой задаче

## Проверки перед коммитом

```bash
npm run typecheck     # tsc --noEmit, обязательно
npm run gen           # если правился scripts/gen-content.mjs
npm run stats         # сверить SKILLS/UPGRADES с README.md и wiki
npm run build         # gen + typecheck + vite build, перед релизным коммитом
```

Числа из `npm run stats` — единственный источник правды по количеству контента.
Любое число в README.md, PLAN.md или wiki, не совпадающее с выводом `stats`, — дрейф,
его надо чинить, а не переписывать вывод.
